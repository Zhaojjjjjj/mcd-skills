# mcd-fitmeal · 麦麦营养师

## 何时使用

当用户表达以下意图时，使用本 Skill：

- 想吃麦当劳，但有热量 / 蛋白质 / 碳水目标（减脂、增肌、控糖、健身餐）
- 询问"麦当劳吃什么不长胖""高蛋白套餐怎么搭""控糖能吃什么"
- 要求制定一周的麦当劳饮食计划
- 已有搭配方案，要求按营养目标优化，或确认后直接下单

## 三种模式与目标定义

| 模式 | 热量默认区间 | 蛋白质下限 | 额外约束 | 搭配策略 |
|------|-------------|-----------|---------|---------|
| 减脂 `cut` | 400–600 kcal | ≥ 30g | 钠偏高时提醒 | 蛋白质密度优先；去酱 / 酱另放；烤替炸；饮料选无糖 / 黑咖啡 |
| 增肌 `bulk` | 700–1000 kcal | ≥ 45g | — | 达标前提下选热量更高组合；可加一份蛋白小食（麦乐鸡 / 牛奶） |
| 控糖 `sugar` | 400–700 kcal | ≥ 25g | 碳水 ≤ 45g | 避含糖饮料与高碳水小食；优先蛋白质 + 蔬菜类搭配 |

用户未指定模式时默认按**减脂**处理；用户给出的具体数字永远优先于默认值。

## 工作流

每一步注明所用 MCP tool（仅使用以下官方 tool，不编造）：

1. **确认目标**：询问模式、热量上下限、蛋白质下限、特殊约束（过敏 / 忌口 / 素食）、用餐方式（到店 / 外送）。
   调用 `now-time-info` 确认当前时段，判断适用早餐还是正餐菜单。
2. **拉取营养数据**：调用 `list-nutrition-foods` 获取官方营养成分（能量、蛋白质、脂肪、碳水化合物、钠等）。
3. **确认在售**：调用 `query-meals` 查询当前门店可售餐品；对候选套餐用 `query-meal-detail` 确认套餐组成与可替换选项。**只推荐在售餐品**。
4. **组合优化**：把营养数据与目标传给 `scripts/meal_planner.py`（确定性脚本，用算法算，不要靠 LLM 心算），取 Top-N 组合。
5. **讲解搭配**：向用户说明每套的总热量 / 蛋白质 / 碳水、为什么达标、替换技巧（如去酱、薯条换玉米杯——具体差值以实际营养数据为准，不要编造数字）、钠摄入提醒。
6. **算价下单**：调用 `calculate-price` 按商品列表（含券）计算应付总价；**用户明确确认后**再调用 `create-order` 创建订单，把订单详情与支付链接交给用户。

## 搭配原则

- **蛋白质优先**：同热量区间下，选择蛋白质密度（g 蛋白质 / 100 kcal）更高的组合。
- **酱料是热量刺客**：优先建议去酱 / 酱另放；是否可替换以 `query-meal-detail` 返回的可替换选项为准。
- **钠摄入提醒**：单餐钠偏高时主动提醒，建议多喝水、当天其他餐次清淡。
- **饮料默认无糖**：可乐选无糖版本，咖啡选黑咖啡；以实际营养数据为准。
- **不推荐硬饿方案**：单餐热量不低于 300 kcal；用户目标明显不合理时，先与用户确认再执行。

## 7 天配餐计划生成规范

- 每天按早 / 午 / 晚三餐设定目标（默认：早餐约 350 kcal、午餐约 550 kcal、晚餐约 500 kcal，可按用户调整）。
- 蛋白质**均匀分布**到三餐，避免"一餐吃够、全天失衡"。
- 同一单品 7 天内出现不超过 3 次，保证多样性。
- 计划开始前用 `query-meals` 确认在售，避免推荐停售单品。
- 输出格式：每日三餐搭配 + 每日营养总计 + 一周下单清单。

## 注意事项

- 营养数据来自麦当劳官方 MCP，**仅供参考**；实际营养成分以门店公示及产品为准。
- 过敏原、配料表请用户自行向门店核实；有食物过敏、慢性病、孕期、未成年人等情况，请咨询医生或营养师——**本 Skill 不构成医疗建议**。
- 下单前必须经用户**明确确认**；涉及支付金额时，向用户复述应付总价。
- 仅使用官方 MCP tool，不编造工具名称、参数与返回字段。
